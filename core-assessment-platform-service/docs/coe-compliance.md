# COE compliance and deviation register

Status of this service against the **GenWorx COE Python FastAPI & AI Agents
Standards** (v1.0.2 / 1.0.3), recorded during the consolidation of the four CAP
backends into one modular FastAPI application.

Every deviation below is deliberate and has a reason. Nothing here is "we didn't
get to it" unless it says so.

Last reviewed: 2026-07-28.

## 2. Deviations

### 1. Async-first is not met in the service layer

**COE:** "All I/O-bound operations must use async/await."

**Status:** partial. Every outbound adapter is async — `httpx.AsyncClient`,
`AsyncOpenAI` — and all routes are coroutines. The service layer between them is
still synchronous, and database access is synchronous SQLAlchemy.

**Why:** the codebase carried ~778 synchronous functions and zero async
SQLAlchemy. Converting the DB layer means `create_async_engine`, `AsyncSession`,
async repositories, and rewriting the three largest business-logic modules
(`assessment_service.py` at 3,453 lines, `question_bank_service.py`,
`evaluation_service.py`) — a larger project than the consolidation it would have
been bundled into.

**Bridge:** `utils/helpers/concurrency.py::run_async`, deliberately concentrated
one-per-adapter rather than scattered across call sites, so it is one line to
delete per adapter when the services become coroutines.

**Owner action:** schedule the async database phase. Until then this is the
largest open gap.

### 2. Compose lives at the service root, and covers its own infrastructure

**COE:** the template places a single `docker-compose.yml` at the service root.

**Met, with a note.** `core-assessment-platform-service/docker-compose.yml` is at
the service root as the template asks. It additionally defines PostgreSQL, Redis
and Judge0, because the service cannot run without them and keeping them in the
same Compose project is what lets `depends_on` gate start-up -- an earlier split
into separate projects broke that and needed a hand-written database wait to
compensate. The SPA has its own file at `frontend/docker-compose.yml`.

### 3. `src/worker.py` is outside the template

**Why:** COE defines no worker slot. The Celery application and its tasks do live
in `control/`, per the template's control layer.

### 4. `mongo_client.py`, `base_mongo_repository.py`, `base_grpc_client.py` absent

**Why:** not applicable. No MongoDB driver and no gRPC surface anywhere in CAP.
The `data/models/mongo/` and `handlers/grpc_clients/` directories are retained as
placeholders, matching the repository's existing convention for unused slots.

### 5. `routes/websocket.py` absent

**Why:** CAP has no WebSocket transport. All three real-time surfaces —
notifications, slot monitoring, AI draft progress — are server-sent events, which
suit unidirectional push and survive proxies better. Adding an empty module to
satisfy the letter of the template would be dead code.

### 6. `ai_gateway.py` does not use tenacity

**COE §8:** "LLM Rate Limits: Implement exponential backoff using tenacity."

**Why:** it is not a retry loop. It walks a sequence of provider targets (model
paired with API-key slot), classifies each failure — rate limit, auth, bad
request, exhaustion — to decide whether to advance a target or abandon the run,
prefers the provider's `Retry-After` header over its own delay, and writes a row
to `ai_run_logs` per attempt. Retry policy and routing policy are one decision
there, and tenacity models only the first.

Exponential backoff, which is what the requirement is actually asking for, is
present in `_retry_delay_seconds`. Tenacity **is** used in
`base_http_client.py` and `groq_code_quality.py`.

### 7. `Settings` is flat, not nested by section

**Why:** proposed during planning, then dropped. It would have touched 183 access
sites across 28 files for no functional change, and COE requires only
`config/settings.py` driven by pydantic-settings, which is met. Section banners
give the navigability at no regression risk.

### 8. SSE handlers are not inside `routes/sse.py`

**Why:** the three handlers stay on their feature routers so each path lives with
the rest of its feature. `routes/sse.py` owns the part that was actually
load-bearing — the shared response builder and its header set. Relocating the
handlers would churn three routers' prefixes for a cosmetic gain.

## 3. Known defects, tracked not deviated

### `core.services.question_bank` ↔ `control.agents` import cycle

`question_bank_service` imports `QuestionGenerationWorkflow`; the workflow's nodes
import `question_bank.output_validation`. Predates the consolidation. Breaking it
means giving the workflow its own validation port. Until it is gone, a
`layers` contract cannot be added to `.importlinter` — see the header note there.

### Evaluation reports need shared storage

In-process evaluation makes whichever process serves a download responsible for
seeing the generated file. Compose shares a volume between the API and the worker.
**Cloud Run does not** — the service and worker pool get separate disks. Report
generation must therefore stay in the request path there, or reports must move to
object storage before generation is handed to the worker.

### CI drift gate does not exercise the deployed schema layout

`.github/workflows/quality.yml` leaves `EVALUATION_DB_SCHEMA` unset, so CI runs the
evaluation Alembic tree against its `evaluation` default. Compose and the Cloud Run
deploy script both set `public`. Both layouts are now verified locally; CI should
run the `public` one too, since that is what deploys.
